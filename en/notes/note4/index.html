GADTs in Haskell

2011-09-11
haskellGADTs

Motivation

Two of Haskell’s most powerful type-level features — GADTs and type families — let you push invariants into types that would otherwise only be checked at runtime.

GADTs

A GADT (Generalised Algebraic Data Type) allows each constructor to refine the return type:

{-# LANGUAGE GADTs #-}

data Expr a where
  Lit  :: Int              -> Expr Int
  Bool :: Bool             -> Expr Bool
  Add  :: Expr Int -> Expr Int -> Expr Int
  If   :: Expr Bool -> Expr a -> Expr a -> Expr a

The typechecker now knows that Lit produces Expr Int and Bool produces Expr Bool, so a well-typed evaluator needs no runtime casts:

eval :: Expr a -> a
eval (Lit n)      = n
eval (Bool b)     = b
eval (Add x y)    = eval x + eval y
eval (If c t f)   = if eval c then eval t else eval f

Type Families

Type families are functions on types. They come in two flavours.

Closed type families

{-# LANGUAGE TypeFamilies #-}

type family Elem (c :: Type) :: Type where
  Elem [a]        = a
  Elem (Maybe a)  = a
  Elem (Map k v)  = v

Associated type families

class Container f where
  type Item f :: Type
  empty  :: f
  insert :: Item f -> f -> f

instance Container [a] where
  type Item [a] = a
  empty         = []
  insert        = (:)

Combining Both

A heterogeneous list indexed by a type-level list of types:

data HList (ts :: [Type]) where
  HNil  :: HList '[]
  HCons :: t -> HList ts -> HList (t ': ts)

type family Head (ts :: [Type]) :: Type where
  Head (t ': _) = t

hhead :: HList (t ': ts) -> t
hhead (HCons x _) = x

The type HList '[Int, Bool, String] is statically known to contain exactly an Int, a Bool, and a String in that order.

Summary

  • Use GADTs when constructors need to refine or constrain the result type.
  • Use type families when you need type-level computation or associated types.
  • Together they enable a wide range of type-safe DSLs and data structures with zero runtime overhead.
