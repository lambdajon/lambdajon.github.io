Dependent Types and Formal Verification in Systems Software

researchtype theorydependent typesverificationsystems

Abstract

We explore the application of dependent type systems to the formal verification of low-level systems code, with a focus on memory safety properties that cannot be captured by simpler type disciplines.

1. Introduction

Systems software operates at the boundary between hardware and the rest of the software stack. Properties such as memory safety, absence of data races, and correct handling of resource lifetimes are critical yet hard to guarantee with conventional testing.

2. Background

2.1 Dependent Types

A dependent type is a type whose definition depends on a value. The classic example is the type of vectors of fixed length n:

data Vec (n : Nat) (a : Type) where
  Nil  : Vec 0 a
  Cons : a -> Vec n a -> Vec (n + 1) a

Safe vector indexing then has the type:

index : Fin n -> Vec n a -> a

The type Fin n represents natural numbers strictly less than n, making out-of-bounds access a type error rather than a runtime fault.

3. Approach

We instrument a subset of a Rust-like IR with a dependent type layer and prove safety properties via refinement types:

// Precondition: buf.len() >= offset + len
fn read_slice(buf: &[u8], offset: usize, len: usize) -> &[u8]
where
    Proof: offset + len <= buf.len(),
{
    &buf[offset..offset + len]
}

The proof obligation is discharged either by the caller supplying an explicit witness or by an SMT solver invoked at compile time.
